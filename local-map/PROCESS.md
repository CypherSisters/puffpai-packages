# How Local Map picks, fetches and sorts

1. **A region becomes a box.** You give a centre (a town picked from the place list on this computer, a tap on the map, or typed latitude and longitude) and a radius, 0.5 to 50 km or 0.5 to 31 miles. The box goes the radius north and south (1 degree of latitude is taken as 111.32 km) and the radius east and west (the same, times the cosine of the latitude). A box that would cross the 180 degree line is refused. The box is then rounded outward to a 0.05 degree grid (west and south down, east and north up), so the middle of what is fetched and sent is not the point you chose. The page shows this rounded box before anything is fetched, and the street map and the places query both use it.
2. **Detail sets the last zoom level.** Small stores zoom 0 to 12, Standard 0 to 14, Detailed 0 to 15. The map draws closer zooms by enlarging the last stored level.
3. **The tile list.** For each zoom from 0 to the last one, the box's corners are turned into tile columns and rows (Web Mercator, the usual z/x/y tiles), and every tile between them is listed. Each tile's PMTiles id is its place on that zoom's Hilbert curve plus the count of tiles in all lower zooms.
4. **The newest map.** Local Map asks build-metadata.protomaps.dev for `builds.json` and takes the entry uploaded last among those whose name is in the daily form (8 digits, then `.pmtiles`). If none is, it stops: "The map host's list of builds was not in the form this app knows. Nothing was downloaded."
5. **The dry run (Check size).** It reads the first 16 KB of that build on build.protomaps.com (the 127-byte header and the root directory), then only the leaf directories that hold the listed tiles. Each listed tile is found by its id: the entry with the greatest id at or below it, inside its run length; an entry with run length 0 points to a leaf directory. No tiles are read in the dry run.
6. **The size and the cap.** The tiles' byte ranges are sorted and merged where they touch or sit within 4 KB of each other (at most 8 MB per request). The size shown is the sum of those merged ranges. If it is bigger than your limit (250 MB unless you change it on the page), nothing is downloaded and the page suggests a smaller detail or radius. Separately, every byte read from the network in one check or download (the list of builds, the directories, the tiles and the places) counts against your limit plus 32 MB, and the job stops when that is passed.
7. **The download.** Pressing Download fetches the merged ranges, cuts each tile out, and writes it into `tiles-partial.sqlite`: one row per tile (z, x, y) and each distinct tile's bytes once (by sha256). Tiles already in that file for the same build, box and detail are skipped, so a cancelled or failed download picks up where it stopped. Before any tile is fetched, every tile entry is checked: at most 4 MB, and inside the tile section the file's header declares; otherwise nothing is downloaded. A tile is stored only when exactly its length was read and, when the file says gzip, it starts with the gzip bytes; any other tile is left out and the page says how many could not be read. The tiles keep the compression the map file says (gzip), and the page is told so.
8. **The emergency points.** Then one query goes to overpass-api.de, with only the rounded box's four edges (south, west, north, east). An answer over 16 MB is refused (choose a smaller region). Places with a position that is not a real number, out of range, or outside the box (plus 0.02 degrees) are dropped; at most 20,000 are kept, the nearest the middle of the region, and the page says how many were left out. Names are kept to 200 characters, addresses 300, phones 60 and opening hours 300. Each result gets one plain kind (Fire station, Police, Hospital, and so on; a ranger station counts as Town hall). Its name, kind, position (a building's centre for areas), address parts, phone, opening hours, the source "OpenStreetMap" and the fetch date are kept. A busy answer (429, 406, 502, 503, 504) or a time-out stops the download with a plain message; it is never retried by itself.
9. **The swap.** Only when both steps worked does the new tile file replace the old one and the new points replace the old points. Until then the old map stays as it was.
10. **What is sent to each host.** build-metadata.protomaps.dev: only a request for the list of builds. build.protomaps.com: requests for byte ranges of one public file, so it can tell which map area was fetched. overpass-api.de: the four edges of the box, rounded outward to a 0.05 degree grid, and the fixed list of kinds. All three see this computer's internet address, and every request names a generic client (`local-map/1.0`). Nothing about you, your home or your own points is sent. Searching for a town happens on this computer.
11. **Sorting.** Distances are straight-line (great circle, haversine, earth radius 6371.0088 km), from home or from a point you name; directions are the compass bearing from there, in degrees and as one of eight words (north, north-east, and so on). Lists are nearest first when home is set, and by kind and name when it is not. There is no routing.
12. **A refresh keeps your points.** Downloading the region again (or a new region) replaces only the fetched points and the tiles. Your own points and home stay. Home is set to the region's centre only when it was not set before, and then the page says: "Home was set to the middle of the map. Change it to your real spot if you like: it is never sent anywhere."
13. **Time and Cancel.** builds.json and each directory request get 30 seconds; each tile range gets 30 seconds or the time it takes at about 20 KB a second, whichever is longer; the places query gets 150 seconds; a whole check or download gets 30 minutes. A watchdog looks at Cancel and these deadlines every 0.2 seconds and cuts a request that is over, even one that is sending a byte at a time, so Cancel takes effect within a second or so and a new check or download can start. Map indexes are unpacked a step at a time (at most 16 MB and 500,000 entries each, 2,000 leaf directories and 128 MB in one job, 64 kept in memory), with Cancel looked at every 4,096 entries.
14. **Finding a town.** The town list (GeoNames, towns of 1,000 people or more) is searched on this computer. Accents and case are ignored, on both the name and its ASCII spelling. A town whose whole name matches comes first, then one whose name starts with the words, then one with the words anywhere in its name; within each, bigger towns come first. At most 20 are shown, each with its state or region and country. Words after a comma narrow the list: each must be the start of the state or region's name, its code, or the country code ("Portland, Maine", "Portland, GB").
15. **Finding a point by name.** A tool given a name looks for an id first, then a whole name, then part of a name by whole words, ignoring case, accents and a leading "the", "our", "my", "a" or "an". Part of a name means each word said is a word of the name or the start of one, three letters at least; never letters inside a word, so "Ron" does not find "Sharon". One match is used, and when only part of the name was said the answer starts with the one used ("Using 'City Hall steps'."). A town is picked the same way: by its whole name or the start of its words, never letters inside one. When none or several match, nothing is changed and the answer names the candidates. `where_is` tries the map's points, then the town list; when several towns share the name, it lists them all instead of picking one.
16. **Saving one of your points.** `save_my_point` finds the name the same way as step 15. One match: that point is changed (only the new name, kind, place or note that was said), and the answer starts "Changed" (after "Using '<name>'." when only part of the name was said). No match: a new point is added with that name (a leading "our" or "my" is dropped), and the answer starts "Added"; it needs a place, home or latitude and longitude. No match with a new name, or several matches: nothing is changed and the answer names the candidates. A place is "home", or two numbers, or one text such as "37.47, -122.43". A kind is read from everyday words ("neighbour", "water"); a word it does not know is stored as Other and the answer says so.
